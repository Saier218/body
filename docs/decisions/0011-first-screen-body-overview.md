# 0011 首屏改为全身概览

- 状态：生效（设计已定，尚未开发）
- 日期：2026-11-22
- 层：结构、框架
- 决定人：产品负责人
- 取代：决策 0010 第 1 条（"打开 App 直接进入手部"）。0010 中左手默认、左右手镜像的做法继续有效。

## 背景

负责人最初的设想是"人体概览 → 点区域进一层 → 再点到更细的部位"。0010 一度改成直接进入手部，负责人随后改回最初设想，并要求层级尽量少。为此做了同类调研：`docs/design/research/2026-11-22-entry-and-navigation.md`。

## 结论

| 事项 | 决定 |
|---|---|
| 首屏形式 | 3D 全身人体，可旋转 |
| 全身外观 | 骨骼加浅层肌肉，不显示皮肤；像同类应用一样不呈现生殖器及其细节 |
| 未做内容的部位 | 灰色显示，点击提示"内容整理中"。第一版亮色部位为手、前臂、肩 |
| 层级 | 三层：全身 → 部位 → 结构。原先"手 → 手指 → 结构"的中间一层取消，点结构时镜头自动推近 |
| 返回方式 | 去掉多级面包屑，改为醒目的返回按钮加当前部位名称；保留一键复位 |
| 左右侧 | 在全身上点哪一侧就进入哪一侧。所有部位页都保留右上角的左右开关，切换时停留在同一部位、同一视角，方便左右对比，不必返回上一级 |
| 屏幕方向 | 手机锁定竖屏；iPad 保留横竖屏（锁方向会失去分屏） |

## 理由

- 全身概览符合最初的产品设想，也是 3D 解剖类应用的主流做法；镜头从全身飞进部位，让人始终知道自己在身体的哪里。
- 手机上层级越深越容易迷路，三层足够把细节送到用户面前。
- 层级浅时，多级面包屑占位置却用处不大；返回按钮更醒目、更好点（同类产品因返回按钮太小被批评）。
- 左右开关留在部位页，是负责人提出的对比需求，调研中没有反对理由。

## 核实

- 安卓 16 起，面向 API 36 的应用在大屏设备上的方向锁定会被系统忽略：据已有知识，未逐条核实。
- 骨骼与肌肉网格来自 BodyParts3D（CC BY 4.0，决策 0001），不含皮肤；开发时需逐个确认排除生殖相关的网格。

## 未解决

- 全身概览模型的面数与真机性能，开发时测量并写入性能预算。
- 除手、前臂、肩外，其余部位怎么切分（仅影响灰色区域的显示），开发时提出方案。
