# 0005 内容数据的结构与校验

- 状态：生效
- 日期：2026-11-16

## 结论

所有内容以 JSON 文件存放在 `content/`，格式由 `content/schema/` 中的 JSON Schema 定义，由 `tools/content/` 校验并打包成 App 读取的单个文件。不建数据库，不建后台。

| 文件 | 内容 |
|---|---|
| `structures.json` | 解剖结构：编号、中英拉丁名、类别、分区、对应的模型网格 |
| `sports.json` | 运动及其动作分类（目前只有攀岩，结构上支持多运动） |
| `movements/*.json` | 动作：涉及的结构及其角色、关联的损伤 |
| `injuries/*.json` | 损伤：概述、机制、文献所述表现、危险信号、一般原则、分级、预防、不确定性 |
| `sources.json` | 文献来源及证据等级 |

## 关键设计

1. **结构与模型分开。** 结构是解剖概念（如"指浅屈肌"），模型网格是它的几何形状。一个结构可以对应多个网格，两者只靠网格编号连接。模型重做或内容重写互不影响。
2. **逐段标注来源。** 损伤和动作里的每一段文字都带自己的来源列表，而不是整条共用一份参考文献。这样能回答"这句话出自哪里"。
3. **三档状态。** `draft` → `sourced` → `expert-reviewed`。打包时草稿被剔除，不会到达用户。
4. **风险只做定性描述。** 格式里没有分数字段，多写字段会被校验拒绝。
5. **手指用通俗叫法。** 中文名用"食指"，不用解剖学标准的"示指"，因为目标读者是攀岩者。标准名称记在术语说明里。

## 校验规则（`npm run content:validate`）

- 格式符合 Schema；编号唯一；所有引用（结构、损伤、来源、运动分类）都能找到
- 模型里的每个网格恰好属于一个结构；结构列出的每个网格在模型中存在
- 非草稿条目：每一段都有来源，且有审阅日期；专家审阅状态必须写明审阅人
- 损伤必须有危险信号和免责声明
- 中英文都不能为空
- 禁用措辞（准则 3.1）出现即失败
- 没有被任何条目引用的来源视为错误

每条规则在 `tools/content/validate.test.mjs` 里都有一个"故意写错"的测试，证明它确实会拦截。

## 已知不足

- 99 个结构的中文和拉丁名是凭已有知识写的，尚未对照术语标准，统一标为 `names_status: unverified`。滑车没有标准拉丁名，未填。
- 原始数据中有一块右手肌肉被标为"左"，对应结构名暂标"来源标签待核对"。
- 英文禁用词按词根匹配，可能误伤个别正常用词，遇到时再调整规则。

## 被否决的选项

- **数据库或内容管理后台**：一人项目不需要，文件加版本管理已经能追溯每次修改。
- **把名称写在模型文件里**：会让改一个译名就要重新打包模型。
