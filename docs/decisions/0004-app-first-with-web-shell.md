# 0004 平台改为 App 优先，外壳用 Capacitor

- 状态：生效（浏览器内的端到端测试已通过；iOS 与 Android 工程已生成，**尚未在 Xcode / Android Studio 中编译或上真机**）
- 日期：2026-11-16
- 取代：决策 0003 中"以小程序为首发平台"的部分。0003 里关于 3D 核心的设计继续有效。

## 结论

1. 首发平台从微信小程序改为 **iOS 与 Android App**。这是产品负责人的决定，理由是 App 的上限更高（模型体积、性能、离线、原生能力）。
2. App 的界面用网页技术编写，由 **Capacitor**（MIT 协议）包成原生 App。3D 核心原样复用。
3. 小程序外壳（`apps/miniprogram`）冻结保留，不再维护，也不删除。

## 为什么用 Capacitor，而不是其他做法

| 选项 | 结论 | 理由 |
|---|---|---|
| **Capacitor：网页界面 + 原生外壳** | 采用 | 现有 3D 核心一行不改；一套代码出 iOS、Android 和网页三个版本；整个界面能在云端用浏览器自动测试，不依赖真机就能发现大部分问题 |
| 原生开发（Swift + Kotlin） | 否决 | 两套代码，3D 核心要重写两遍，一人公司维护不了 |
| React Native + 原生 GL | 否决 | 能复用核心，但 3D 桥接层多一层未知数，且无法在浏览器里测试 |
| Unity 等游戏引擎 | 否决 | 核心要重写；包体大；做普通界面（文字、列表、表单）很别扭 |
| Flutter | 否决 | 3D 支持弱，核心要重写 |

## 这次换平台的代价（如实记录）

- **传播变难。** 小程序扫码即用，App 要下载。这与"影响力优先"的目标有冲突。缓解：同一套代码可以直接发布成网页，用于分享链接和内容引流；冻结的小程序外壳日后可作为轻量入口复活。
- **上架门槛更高。** 以下均为凭已有知识列出，**执行前须逐项对照官方当前要求核实**：
  - 国内上架须 App 备案；安卓各应用商店普遍要求软件著作权登记证书。
  - 苹果开发者账号按年付费；以公司名义注册需要邓白氏编码。
  - 编译 iOS 版必须有一台 Mac。
  - 首次启动须有隐私政策弹窗并取得同意后才能收集任何信息。
- **界面是网页渲染的。** 做得粗糙会显得"不像原生"；苹果对"只是把网站包一层"的 App 有拒审风险（未核实具体条款）。我们的内容全部打包在本地、有完整交互，风险较低，但界面质感要认真做。

需要纠正的一点：小程序的 2 MB 包体限制并不是硬伤，模型可以从服务器下载，当时也没有任何功能因此被砍。换平台的真正理由是长期上限，不是眼前做不了。
