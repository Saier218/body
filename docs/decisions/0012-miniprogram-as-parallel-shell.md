# 0012 小程序恢复为并行外壳

- 状态：生效（页面已编写；从未在微信开发者工具或真机中运行）
- 日期：2026-11-23
- 层：范围、工程
- 决定人：产品负责人（恢复小程序）；实现方式由开发决定
- 关联：决策 0004（App 优先）继续有效；本决定只改变小程序"冻结"的状态

## 背景

负责人暂时没有 Mac，也没有安卓手机，App 的真机测试和发布推迟。微信开发者工具能在 Windows 上运行，预览时用任何装了微信的手机扫码即可，是目前让负责人在真机上看到产品的最快途径。

## 结论

- `apps/miniprogram` 恢复为与 App 并行的第二个外壳，共用 3D 核心、内容数据、界面文字和设计变量。
- App 仍是正式发布的目标；小程序先用于测试，日后可作为轻量入口。
- 共用部分由 `tools/build-miniprogram.mjs` 生成进小程序目录：3D 核心、文字表（`packages/shared`）、压缩后的模型、内容数据包。生成结果提交入库，打开项目不需要先装开发工具链。

## 代价

- 界面要写两遍：App 用 React，小程序用微信自己的页面语言（WXML）。为控制成本，小程序暂时只保证"身体"标签与 App 一致，其余标签跟随 App 定稿后再补。
- 主包上限 2 MB。目前约 1.7 MB；为此把全身概览简化到约 3.7 万面（决策 0011）。部位和内容增加后，模型需要改为分包或从服务器下载，后者需要已备案的域名。

## 未核实

- 用"测试号"能否在真机上预览：据已有知识，正式预览需要真实的小程序 AppID；负责人有公司主体账号，可以新注册一个小程序。
- 小程序画布对 WebGL2 的实际支持、压缩模型的读取，均待在开发者工具和真机上验证（决策 0003 中的 H2–H5 仍未验证）。
