# 损伤标签首页与"哪里不舒服"入口：两个方案

- 日期：2026-11-23
- 状态：待负责人选择（方案阶段，尚未写决策记录）
- 层：结构、框架（用户体验五层中的第 3、2 层）
- 调研：`docs/design/research/2026-11-23-injury-browsing.md`
- 怎么看：用浏览器打开本文件夹里的 `index.html`，四个手机框并排，框内可以滚动和点击。截图在 `shots/`（`*-scrolled.png` 是滚到底部的样子）。

页面里的条目名称、数量（"x 条"）和日期都是**示例文字**，不是医学内容。A2 滑车损伤在数据里目前是 `draft`（草稿），按准则 5.3 正式版不会出现在列表中；样稿里它带"示例"标记，点它会打开已有的详情页样稿 `docs/design/mockups/a/injury.html`。

## 先说要解决的问题

产品纲领里用户要完成的事排在首位的是："有不适或刚受伤时，想弄清这里是什么结构、文献里这种伤是怎么回事、什么情况必须去医院。"这群人进"损伤"标签时，往往**知道哪里不舒服，但不知道这叫什么**。所以首页要让他们按身体部位找到相关条目，同时守住红线：**这是一本书的目录，不是症状自测**。

## 方案一 · 部位目录（推荐）

**思路。** 首页上半部分是一个小号的 2D 人体图（可切换正面 / 背面）和一列部位名称，两者并排、作用相同：点人体上的亮色部位，或点右边的名称，都进入同一个结果页。下方是"什么时候应该尽快就医"卡片和"全部损伤（按名称排列）"入口。结果页先用一个说明框写清"这是目录，不是判断"，再放就医卡片，然后是该部位的条目列表，可以按结构类型（滑车、肌腱、关节与韧带、骨与生长板）筛选。

**服务哪个用户任务。** 任务一（有不适，想知道这里是什么、文献怎么说、何时就医）。从打开标签到看到条目：点"损伤"→点"手指"→点条目，三次点击，符合 `app-structure.md` 设计原则 1。

**和现有结构的关系。** `app-structure.md` 已写明损伤标签首屏是"按分区分组的损伤列表，顶部搜索"。方案一是它的细化，不改变页面地图。部位划分和"身体"标签（决策 0011）一致：亮色为手、前臂、肩，其余灰色"整理中"。

**优点**
- 和专业学会科普网站（如美国骨科医师学会的"按身体部位"菜单）同一种组织方式，用户不用学。
- 人体图和列表等价，人体图点不准时（手指在全身图上很小）直接点列表；满足"3D 之外有列表式等价入口"（准则 6.9）。
- 实现便宜：结构数据里已经有 `region`（拇指、食指……前臂）和 `kind` 字段，损伤条目又关联了结构，所以"哪个部位有哪些损伤"可以**自动推出来**，不必给损伤条目加新字段。只需要一张"浏览部位 → 结构 region"的对照表（例如"手指"= 五根手指的 region）。
- 首页上半屏信息量大但不拥挤，人体图本身也提示了"灰色部位还在路上"。

**缺点**
- 2D 人体和"身体"标签的 3D 人体是两种画法，观感不完全统一。
- 手指在全身图上很小，真机需要把人体上的可点区域做得比画出来的大（样稿里的 `.bm-hit` 预留了这层隐形点击区，未画出）。
- 部位相同、名字相近的条目多了以后，列表可能变长，需要靠结构筛选。
- 首页在 390×844 屏上略超一屏，"全部损伤 A–Z"入口要稍微下滑才能看到（就医卡片在首屏内）。

**实现成本提示。** 低到中。人体图是一张内联 SVG，正反两面各一张；结果页是普通列表。主要工作在：部位对照表、按结构 `kind` 生成筛选芯片、搜索索引（只收名称、别名、结构名）。另需一个"通用就医信号"页面，这是新内容，要按准则第 5 节逐条找来源。

## 方案二 · 攀岩情境入口

**思路。** 首页先放就医卡片，然后是四张"攀岩情境"卡片：手指在小点上受力时、摔落与落地、肩部过顶与大幅动作、长期反复训练之后；下方是部位网格（亮色 4 个，灰色 3 个，加一个 A–Z）。结果页同样以"手指"为例，但条目按"文献描述的发生情境"分组，可以切换成按名称排列；同一条目可能出现在多个情境里（如"也见于：长期训练"）。

**服务哪个用户任务。** 任务一，兼顾任务二（某个动作哪里容易伤，用于预防）。攀岩者回忆受伤时往往先想到"当时在做什么"（"抓小点时脚滑了"），情境入口贴近这种说法。这是假设，没有用户访谈验证。

**优点**
- 有攀岩特色，别的通用损伤网站没有这一层。
- 情境卡片在首页上视觉分量足，内容量少的时候也不显得空。
- 结果页的分组让用户顺带了解"同一部位的伤，发生方式不一样"。

**缺点**
- 和"动作"标签的分类（抓握方式、身体姿态、动态动作、坠落与落地、专项训练）**明显重叠**。两个标签都在讲"在做什么时伤到"，用户可能不清楚该去哪个；长期要维护两套一致的分类。
- **内容成本高**：每个"条目 ↔ 情境"的关联本身就是一条论断，按准则 5.1 必须有来源。需要给损伤 schema 加一个带 `sources` 的情境字段，并为每条补文献。
- **合规上更敏感**：情境加部位两层组合，离"选条件 → 缩小范围"只有一步。如果日后有人提议"情境和部位同时选，交叉筛选"，那就开始像问卷了（见下文边界）。
- 改变了 `app-structure.md` 里损伤标签首屏的定义，选它需要写决策记录并更新该文件。

**实现成本提示。** 中到高。界面本身不难，难在数据：新增情境字段与 schema 校验、每条关联的来源、与"动作"标签分类的对应关系。

## 两个方案怎样守住"不做症状自测"的边界

准则 3.1 写明不做"输入症状 → 给出判断"的功能。两个方案都只做**目录**，具体靠下面这些设计：

| 风险点 | 做法 | 在样稿哪里看 |
|---|---|---|
| 搜索变成"输入症状得结论" | 搜索只检索条目名称、别名和结构名（中英文与拉丁名）；占位提示写"搜索损伤名称或结构，如'滑车'"。不解析"手指疼""肿"这类描述，搜到的只会是已审核的条目 | 两个首页顶部 |
| 排序暗示"你更可能是哪个" | 结果固定按名称（方案二组内按名称）排列，页面上写明"不按可能性排序"。英国药监机构的指南提到，按严重程度或匹配概率对结果排序的软件可能属于医疗器械，所以排序方式本身就是边界 | 两个结果页的说明框、"按名称排列"标签 |
| 部位选择变成问卷 | 只有一步选择（选部位，或选情境），选完直接是列表，没有追问。筛选芯片按**结构类型**分，不按表现或感觉分 | 结果页芯片 |
| 措辞替用户下结论 | 统一用"文献中常见于手指的攀岩相关损伤"，不出现针对个人的推断句式（如"符合你的情况"）。说明框标题直接写"这是目录，不是判断"，并提示"列表不能告诉你是哪一种，不确定时请线下就诊" | 结果页说明框、方案一首页导语、方案二首页底部提示 |
| 就医路径不够显眼 | 首页和结果页都有暖色的"什么时候应该尽快就医"卡片（全站唯一暖色，与详情页的就医块同色），结果页里它放在列表之前并加粗边框；每个条目详情页里还有该损伤的专门清单 | 两个方案四屏都有 |
| 免责声明只出现一次 | 底部固定一行"本内容为运动科普，不能替代医生的面诊与判断"，滚动时也在 | 四屏底部 |
| 未审核内容混进来 | 每行显示状态徽标（"已对照来源 · 日期"或"专业人士已审阅 · 日期"）；草稿不出现，只显示"另有 x 条正在整理，对照来源后才会上线" | 结果页列表 |

**以后要警惕的提议**（出现时先回到战略层讨论）："部位和情境同时选""按你选的部位把危险的排前面""根据你的日志推荐相关条目""加一个问几道题帮你找到条目的向导"。这些都会把目录变成症状自测。

## 我的建议

**选方案一。** 理由：它直接服务首要任务，层级浅；和现有页面结构、"身体"标签的部位划分一致，不用改结构文档；数据上可以从已有字段推出来，成本低；边界清楚，只有"选部位 → 看目录"一步。

方案二的"情境"思路有价值，但它和"动作"标签重叠，又要求为每个关联补来源。建议先把它记入 `docs/product/ideas.md`，等做完纲领第六节建议的攀岩者访谈（问"上次受伤时你是怎么描述、怎么查的"）再决定。如果访谈发现大家习惯按情境回忆，可以考虑在方案一的结果页里加一个"相关动作"链接跳到"动作"标签，而不是在损伤标签里另起一套分类。

## 需要负责人决定或确认的问题

1. 选方案一还是方案二（或"都不要，因为……"）。
2. 人体图用 2D 还是复用"身体"标签的 3D 全身模型的缩略版？我建议 2D：轻、快、点得准；3D 留在"身体"标签。
3. 通用的"什么时候应该尽快就医"页面是新内容，需要按准则第 5 节找来源，并由专业人士审阅。要不要列入 0.2 骨架版本？
4. 浏览部位怎么切分：样稿用"手指 / 手掌与手腕 / 前臂与肘 / 肩"。结构数据里的 region 还有 elbow、upper-arm，肘是否单列？
5. 青少年攀岩者相关的内容（如生长板）是否在列表中加单独标记？现在只作为"骨与生长板"筛选项出现。

## 课堂小结：这次怎么做的

**做了什么。** 先读了准则、产品纲领、页面结构、决策 0011 和 A2 滑车损伤的数据；再做了 10 次网络检索（同类科普网站与应用、症状自测工具的准确性研究、各国对症状自测软件的监管）；然后画了两个结构不同的方案，每个两屏，用设计变量（tokens，一组统一的颜色、字号、间距数值）保证和方向 A 一致；收尾时用 Playwright（一个能自动打开网页并截图的工具）在 390×844 的手机尺寸下截图，逐张检查后修了三处问题：方案二首页的提示语被底栏挡住、方案一结果页说明文字过长、两个小图标画得不清楚。

**为什么这样做。** 准则 1.8 要求重要页面先调研；准则 3.1 要求不做症状自测，所以两套方案都从"目录"出发，再比较"按部位"和"按情境"两种目录结构。

**放弃了哪些选项。**
- 选部位后继续提问的"向导"：属于症状自测，排除。
- 纯 A–Z 列表作首页：便宜，但不知道名字的人找不到；保留为次要入口。
- 首页直接用 3D 人体：和"身体"标签重复，手机上点手指不准，且更重。

**遇到的限制。** 应用商店页面和部分网站（美国骨科医师学会、一篇期刊评测的原文）在当前环境里打不开，相关信息来自检索摘要，调研文件里已注明是二手信息。法规结论只到"检索摘要"的程度，执行前要对照官方当前文本核实。全页截图时底部固定栏会出现在页面中间（截图工具的限制），所以改成"滚到底部再截一屏"。
